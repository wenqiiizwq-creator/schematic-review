# 原理图审查报告模板 V2.2

报告让设计者迅速进入可执行修改。适用于首审、PDF更新复审、历史意见闭环及仅报告改写。
字段见[review-results-schema.md](review-results-schema.md)，
等级见[severity-calibration.md](severity-calibration.md)。

## 开头最多一页

短标题、版本/范围、简要结论、三个等级数量及3–5条最优先修改（不足按实际数量）。
PDF第2页直接进入“已确认问题及详细修改方法”；没有确认问题则进入风险或建议详情。
不另做独立封面、长目录、方法论、免责说明、全量清单或哈希表。Markdown同样短摘要后接详情。
ID仅用于追溯，等级只用error / warning / suggestion；证据和处理状态用中文单列。

## 1. 已确认问题及详细修改方法

展开全部非suggestion确认问题，按error、warning和实际修改先后排列。

    error | F-001 | 具体标题
    位置：实际PDF页、页名、位号.物理脚、网络、配置
    证据与处理状态：中文说明是否核实、实际修改、复验
    连接与参数：当前连接、值、贴装及来源
    设计依据：原厂文档版本/页码/条款、适用模式、限值
    风险原因与影响：推导链、触发工况、影响范围及未知后果
    归类理由：为何属该等级；有无独立保护
    详细修改：目的、准备度、前提/取得方法、顺序步骤、旧→新端点
    参数：适用的阻值/精度/功率/耐压/封装/装配，已选/候选/待定与依据
    联动：相关ID，供电、默认态、时序和接口影响
    复验：编辑/计算/实测的测点、工况、方法和预期连接/数值窗口
    证据定位：持久本地文件路径/官方URL及页码或表号

复杂支路给连接表或小图。缺输入给条件方案，不编造确定参数、替代料号或空闲GPIO。
每项都展开，摘要不能替代详情。见[remediation-guide.md](remediation-guide.md)。

## 2. 风险项及验证方法

全部非suggestion未决风险通常为warning。保留已知事实、具体机制、缺失输入/工况、
获取方法、条件修改、参数依据、验收和证据。未证实的后果不能写成已确认损坏。

## 3. 建议项及处理方法

全部suggestion集中本节，保留原ID、位置、已知事实、归类理由、步骤、完成条件和证据。
物料/字段问题说明如何核完整MPN、真实焊盘、符号和BOM；文档修正可一步，不套无关上电测试。
资料待补与已满足要求后的可选改善分别说明，不能因建议级而丢失未决输入。

## 4. 附录与索引

详情之后放计算/修改后复算、需求、页面/器件/物理脚/轨/链路/状态/平台条款覆盖、
冷/热候选处置、历史更正、专业交接、版本哈希、完整条目索引和校验结果。
长表可链接持久JSON/CSV或附件；不得为缩短前言删掉覆盖与证据。PDF用书签导航，长目录可后置。

## 生成与交付校验

scripts/render_report.py从已验证v3台账生成Markdown详情和三等级CSV，不代替工程判断。
PDF使用环境现有文档工具排版。确认前置最多一页、第2页进入详情；渲染全部页面检查
裁切、重叠、乱码和密集表格。核对PDF/Markdown、索引、CSV、JSON的唯一ID、等级和数量。
脚本成功不等于排版合格。

仅更新PDF：先比较哈希、逐页差异及网表，沿变更依赖复验。
仅改报告：保留旧版并比较前后技术事实、详细改法、未知条件和结论；
“改等级/排版”不能写成“修复电路”。未经用户要求不修改源设计。

## 新绑定与复审台账

新报告使用 schema_version=3、binding_version=1、remediation_version=1。
生成时与校验使用同一最终计划、db和冷/热lint，并传--require-bindings。
复审另传--old-db、--old-plan、--require-revision-impact；不得用缺历史快照的报告冒充复验通过。
绑定/复验统计放详情后的附录，逐项证据和方法保留在JSON；不能增加长前言。
